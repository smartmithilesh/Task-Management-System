# Mobile push notifications

The optional push channel uses Firebase Cloud Messaging HTTP v1. Set `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, and `FIREBASE_PRIVATE_KEY` from a dedicated Firebase service account on the Laravel host. Enable the Firebase Cloud Messaging API and grant only the permissions needed to send messages. Never put the service account key in the web bundle, Flutter app, logs, or repository. `FIREBASE_PRIVATE_KEY` may contain literal `\\n` line breaks when supplied through the host's environment UI.

When all Firebase server credentials are present, the notification preference API exposes the `push` channel. Task assignment and mention notifications queue one delivery job per registered device. FCM access tokens are minted from a short-lived signed service-account assertion and cached; device registration tokens are encrypted at rest, deduplicated by SHA-256 hash, and never returned by the API. Unregistered FCM tokens are removed. Other provider errors retry with backoff.

The signed-in mobile app asks for permission only when the backend advertises push, registers its FCM token with `POST /api/v1/push-devices`, updates that registration after token rotation, and removes it on sign-out. Foreground messages appear in-app; tapping a task notification opens that task. `DELETE /api/v1/push-devices/{device_id}` removes only the current user's device registration. Follow Firebase's [Flutter project setup](https://firebase.google.com/docs/flutter/setup) and [Cloud Messaging Flutter guide](https://firebase.google.com/docs/cloud-messaging/flutter/get-started) for platform registration and APNs setup.

For Android/iOS builds, create native Flutter platform projects and connect the app to the Firebase project with FlutterFire. Add the Firebase Android app configuration and iOS `GoogleService-Info.plist`, enable Android notification permission, enable iOS Push Notifications and Remote notifications background mode, and upload the APNs authentication key to Firebase. Then run `flutter pub get`, `flutter analyze`, and `flutter test`; validate delivery on physical Android and iOS devices before enabling push preferences for users. Without Firebase server credentials, the backend leaves push preferences unavailable and continues in-app/email notification delivery.
